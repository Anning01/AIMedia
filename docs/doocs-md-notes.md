# doocs/md 学习笔记

> 结论先行：万稿汇的模板系统与 doocs/md 是同一路线，但此前「编辑器预览」和「复制到公众号的导出 HTML」各自实现，导致导出丢失了大量模板版式。本次已把导出层重构为与预览同源，并补齐了微信粘贴兼容处理。

## doocs/md 的核心架构（v2）

1. **同一渲染器，两个出口**
   基于 `marked` 的自定义渲染器把 Markdown 渲染成带语义 class 的 HTML（`h1`/`p`/`blockquote`/`li`…），预览和导出用同一份结构；导出时用 `juice` 把主题 CSS 全部内联成 `style=""`，并关闭 CSS 变量解析、随后手工把 `var(--md-primary-color)` 等替换成具体色值——因为微信编辑器不认 CSS 变量。

2. **主题 = 分层 CSS，而不是每套模板写死**
   `base.css`（元素级排版：字号、行高、边距、变量定义）→ 主题 CSS（`default`/`grace`/`simple`，只覆盖组件样式）→ 用户自定义 CSS。全部用 `--md-primary-color`、`--md-font-family`、`--md-font-size` 驱动，换色即换变量。主题选择器统一 scope 到 `#output`，导出时再剥掉 scope 交给 juice 内联。

3. **标题样式预设**
   每级标题支持 `color-only` / `border-bottom` / `border-left` / `custom` 四种预设，按层生成 CSS 注入，这是「模板不止换色」的关键之一。

4. **内置组件库**
   JSX 风格自定义组件：`TipBlock`、`TableBlock`、`InfoGrid`、`BadgeGroup`、`AuthorBlock`、`QRCodeBlock`、`MpProfile` 等。模板字符串里用 `{{prop}}`、`{{#if}}`、`{{#each}}` 渲染，颜色用带浅色兜底的 CSS 变量（`var(--md-comp-xxx, #fff)`），既支持编辑器深色模式，又保证粘贴到微信时回落到浅色。

5. **微信粘贴兼容处理**（clipboard-dom）
   - `li > ul/ol` 从 `li` 中移出（微信会重置嵌套列表）；
   - `img` 的 `width/height` 属性转成内联样式；
   - 首尾各插入一个零尺寸空段 `p`，避免微信重置首个节点；
   - `top: Xem` 转 `transform: translateY`；
   - mermaid/KaTeX/SVG 做微信专用清洗。

## 本次已落地到万稿汇

- **导出与预览同源**：`src/utils/articleHtml.ts` 重写，`buildInlineHtml` 现在完整实现全部模板变体——标题（bar-left/center-deco/badge/underline）、小标题（number/bar-left/pill/center-dot/underline + steps 编号与连接线）、引用（left-bar/big-quote/bubble/bracket）、卡片（flat/side-bar/top-bar/dashed/glass）、分割线（dot/line/dashed/gradient/icon）、CTA（gradient/pill/dark/outline）、清单（dot/number/check）、纸张与衬线，全部输出内联样式。
- **微信粘贴兼容**：导出的 HTML 首尾自动加零尺寸空段；全程不出现 `var()`/`class`。
- **新增组件块**：信息卡（InfoGrid，2 列分行布局）与标签组（BadgeGroup），编辑器预览与导出一致。
- **引用样式修正**：`left-bar` 引用此前被预览 CSS 写死为橙色底，已改为随主题色。

## 已按此路线完成（2026-08）

1. **微信深色模式预览**：手机预览新增深色开关，通过 `.wechat-dark` 语义化重映射（背景转深、正文转浅、品牌色保留），并对 `--tpl-*` 变量加 `!important` 以覆盖容器内联变量；已用真实渲染截图 + 视觉模型核对对比度。
2. **图床接入**：文章图片支持本地选择（Electron 文件对话框，base64 内联，粘贴到公众号时由微信自动上传）；设置页新增图床配置（本地 / 阿里云 OSS / 七牛 / 腾讯 COS / S3 兼容 / 自定义上传接口），配置存到 `config/imagehost.json`，云厂商 SDK 上传留待接入发布 API 时实现。
3. **主题生成器**：字号（13-20px）、行高（1.5-2.2）、字间距、首行缩进、正文字色、标题颜色、八类版式变体覆盖、自定义 CSS；预览与导出共用同一份覆盖（`src/data/themeOverrides.ts`），支持「另存为我的模板」并在模板列表管理。
4. **导出同源再强化**：主题覆盖的所有参数都进入 `buildInlineHtml`，包括标题色同步到小标题（修复过一次预览/导出不一致）。
5. **排版分块轮**：生成定稿后追加一轮 LLM 调用（`formatArticleBlocks`），只划分结构、不改写原文，输出 blocks JSON 直接渲染进排版模板；前端保留按行解析兜底。
6. **模板示例优化**：8 套模板各有贴合分类的真实示例文案，缩略图按骨架真实渲染（横幅/卡片分组/步骤编号），不再是空壳色块。
7. **第一轮框架规划**：新增 `createFramework` 作为管线第一轮——只根据“用户输入 + 所选模板”定出标题、副标题、分节小标题、金句、清单位、行动号召的完整骨架，后续写作（日文中间稿 → 中文回译）逐字沿用框架小标题，最终分块与模板结构完全一致；译文非中文时自动切换 LLM 直译兜底。
8. **主题生成器实时预览**：生成器改为右侧抽屉，所有调节（字号/行高/字距/颜色/版式变体/自定义 CSS）实时反映在左侧文本编辑器中，满意后点「保存到当前模板」或「另存为我的模板」；取消关闭即还原。
9. **骨架与模板扩容**：整体骨架从 5 种扩到 8 种（新增时间线、问答卡、目录式），内置模板从 8 套扩到 12 套（t9 时间轴复盘、t10 问答手册、t11 目录速读、t12 夜谈时间轴），并配套示例文案、导出渲染与深色模式样式。
10. **管线回归参考项目核心**：删除第一轮框架规划与所有模板结构硬约束，文章生成严格按参考项目 `QUALITY_MODE=fast` + `ARTICLE_REWRITE_MODE=rebuild`（人性化日文规则 → 有道回译）；排版分块仅保留在最后一轮，只做样式映射、不改写原文；译文非中文时保留 LLM 直译兜底防英文输出。
11. **界面按钮全部接真**：文章保存草稿/存入草稿箱、贴图导出 PNG/上传本地图/AI 生图/素材库、笔记解析与候选生成（LLM）、配图真实渲染、发布中心（草稿箱/发布队列/账号凭证/真实发布接口）、任务中心（持久化/立即执行真实生成/真实日志/导出）、工作台统计、设置页（开机自启/数据目录/发布与图片接口/用量与账单导出）全部读写真实本地数据或调用真实接口；未配置接口时给出明确报错，不再有“预留/演示”假成功。
12. **公众号文章配图**：生成区支持「不配图 / 上传图片（1-3 张）/ AI 生成（1-3 张）」；上传走多图选择，AI 生成按主题分别产出场景图、概念图、氛围图并自动存入素材库；生成后按“段落组聚类 + 内容长度近似”自动插入图片块——图只落在完整段落之间、按全文长度大致均匀分布，不按字符硬切、不截断段落；预览与导出（base64 内联）一致；输入框加高为多行文本域，并移除“生成逻辑”说明。
13. **日文中间稿语言守卫（去 AI 核心修复）**：参考项目原提示词只有日文指令，DeepSeek 会直接输出中文，导致“日文中间稿 → 中文回译”变成中文透传、去 AI 失效（在参考项目本体上复现相同现象）。修复：不改模型、不改流程，仅在该环节加入显式“必须用日语写作、禁止中英文”硬性要求，并在生成后检查假名（片假名/平假名），非日文自动带警告重试一次。验证：DeepSeek 下日文稿假名数 1574，中文回译恢复机器翻译质感，h2 分节正常、模板可跟。
14. **不改原文可补小标题**：排版分块轮在原文没有小标题时，允许在完整段落之间划分 2-4 节并为每节生成 ≤14 字小标题，正文任何句子都不改动；前端另有兜底：若分块轮漏加且正文 ≥4 段，用段落开头短语自动生成小标题。验证：纯叙事文自动补 2 个小标题且正文逐句来自原文。
15. **图片生成统一 MiniMax image-01**：贴图工坊、文章配图、笔记配图默认走 MiniMax image-01（`response_format=base64`，返回 `data.image_base64` 数组）；Key 留空时自动复用「AI 供应商」里配置的 MiniMax Key。已用真实接口验证 HTTP 200、base64 图片返回正常。
16. **AI 生图中文文字实测结论**：MiniMax image-01 无法可靠渲染中文文字——实测“要求显示简体中文「轻断食」”会输出乱码假字，而“禁止任何文字”则完全无文字。结论是模型能力限制，不是提示词问题。对策：所有 AI 出图提示词统一追加“禁止出现任何文字/字母/数字/水印/logo”，中文文字一律用模板/画布图层叠加（真实中文）。
17. **生图风格体系**：新增 6 档图片风格（爆款吸睛/明亮生活/高级简约/国风雅致/深色科技/杂志胶片），默认「爆款吸睛」（高对比、浓色彩、强主体、商业摄影质感）；设置页可全局切换，贴图工坊弹窗内可临时切换，小红书配图优先参考爆款解析出的图片风格。实测默认风格出图为电影级强视觉冲击，无文字水印。
18. **生图人物要求**：所有 AI 出图提示词统一追加“画面内容根据主题自然决定：该有人的场景自然出现人物，不需要人物的场景保持纯净；出现人物时必须是中国人（东亚面孔），年轻、五官精致、干净好看”。三张文章配图按“具体场景 / 视觉符号 / 氛围光影”分工描述画面，避免模型凭空加人。实测通勤咖啡自然出现年轻中国女性，轻断食则生成融合自然的画面，均无文字水印。
19. **默认风格改为电影质感真实**：用户反馈唯美插画风不可接受，新增默认风格「电影质感真实摄影」（真实照片质感、电影级调色、浅景深、剧照感，并明确禁止插画/卡通/二次元/数字绘画/超现实/AI绘画感），全部生图默认使用。实测通勤咖啡与轻断食均为真实摄影质感、无文字水印。
20. **关闭 MiniMax 图片水印**：图片上出现文字/水印的根因是 MiniMax image-01 默认开启可见水印。已在请求体显式传 `watermark: false`，实测生成图完全干净，无文字、水印、logo。
21. **图片库管理**：公众号文章页新增图片库弹窗——选择配图时打开，支持网格浏览、按标签/名称筛选、多选（最多 3 张）、批量上传入库、编辑标签分类、删除；图片库全局共享（贴图工坊入库、AI 生成图自动入库存档，均可复用与打标签）。
22. **图片标签规则**：所有 AI 生成图入库时自动打上「AI生成」标签（文章配图/贴图背景/笔记配图）；用户上传图片必须先填写标签（逗号分隔、必填）才能入库，不再默认「未分类」。
23. **文章自动保存与回载**：每次生成成功的文章（含配图块、模板）自动存入本地「生成记录」（最多 12 条，超出容量自动丢最旧）；点击记录即可把文章和模板重新载入编辑器，支持删除与清空。
24. **小红书笔记真实抓取（复刻图文）**：调研结论是小红书没有官方开放接口，也没有可整包进 Electron 的开源 SDK；选用 `xhshow-js`（MIT、Node/TS 原生、无 Python 依赖）生成 Web 端 `x-s`/`x-s-common`/`x-t`/trace 签名，主进程动态 import 后调 `POST https://edith.xiaohongshu.com/api/sns/web/v1/feed`。解析链接里的 `note_id` + `xsec_token`，返回标题、正文、标签、作者、互动数与原图 URL；前端小红书复刻页新增「读取账号（Cookie）」选择，链接解析后展示爆款图文预览，支持「原图入库」（自动打「爆款参考/小红书」标签）和配图槽位「爆款原图」模式（¥0、可手动指定原图）。Cookie 在发布中心账号管理里维护，只存本机；无 Cookie / 缺 `xsec_token` / 触发验证码都会给出明确报错，不再假成功。
25. **发布中心扫码登录（公众号 / 小红书）**：添加账号改为弹窗扫码登录，不提供手动填 Cookie 的入口。公众号走微信公众平台登录接口（`bizlogin?action=startlogin` 拿 uuid → `scanloginqrcode?action=getqrcode` 出二维码 → `action=ask` 轮询 → `bizlogin?action=login` 取 Cookie + token）；小红书走官方 Web 扫码接口（`/api/sns/web/v1/login/qrcode/create` 出二维码，`qrcode/status` 轮询，登录后自动取 Cookie），二维码用 `qrcode` 本地生成；登录成功自动回填 Cookie。头条号暂不支持。
26. **小红书复刻改为“风格资产 + 产品库”**：拆解结果（选题角度、标题公式、正文结构、情绪词、标签、图片风格、构图与风格思路）可保存为风格资产，之后选择任意已保存风格 + 产品库里的产品即可直接生成新笔记，不需要每篇都重新解析。产品库支持新建/编辑/选用/删除（名称、卖点、目标人群、客单价）。配图不再直接搬爆款原图，而是把拆解出的构图与风格思路作为 AI 配图提示词重新生成；原图仅保留在拆解报告中作构图参考，可手动入库。
27. **产品主图资产**：产品库每个产品必须上传一张主图（选填最多 3 张场景图），上传时自动压缩到 1000px 内，产品列表与选择器展示缩略图；保存产品时校验主图必填。配图槽位新增「产品主图」模式（0 元、产品绝对真实），可直接用于产品特写/封面；AI 场景图提示词强制带上产品外观描述（可手填，不填自动用产品名称+卖点生成），保证生成图中产品外观一致。
