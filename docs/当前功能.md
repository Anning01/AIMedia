# AI Media 改版需求

## 产品定位

AI Media 是一个以对话为入口的文章改写与发布工具。

它只有两条核心链路：

1. Agent 帮用户求实、改稿和配图。
2. Agent 控制浏览器，把最终文章发布到目标平台。

## 一、对话式改稿

用户打开文章后，直接通过对话提出要求，例如：

- 核实文章中的新闻和事实。
- 搜索最新资料并补充来源。
- 修改标题、结构、语气或写作风格。
- 缩写、扩写或重写指定段落。
- 根据已安装的 Skill 执行特定写作方法。

Agent 使用 Firecrawl 搜索和求实。事实结论必须能看到来源；无法确认的内容要明确提示，不能当作事实写入文章。

每轮修改都生成可预览的草稿差异，由用户决定接受、继续修改或恢复历史版本。

## 二、Skills

系统采用与 Codex 相似的 Skills 机制：

- 内置常用 Skill，例如新闻求实、标题优化、结构重写和平台风格适配。
- 用户可以安装、启用、停用、更新和卸载 Skill。
- Skill 可以包含说明、提示词、参考资料和需要使用的工具。
- 对话中可以自动匹配 Skill，也可以由用户明确指定。
- 每次执行都要显示正在使用的 Skill，避免隐藏行为。

## 三、文章配图

配图必须分成两步：

1. Agent 根据文章内容生成图片提示词，交给用户确认或修改。
2. 用户确认后才调用图片模型生成图片。

支持：

- 文生图。
- 图生图，用户可上传参考图并说明修改要求。
- 生成结果预览、重新生成和插入文章。

未经用户确认，不得直接消耗额度生成图片。

## 四、浏览器发布

发布不以 Webhook 为主要方式，而是由发布 Agent 控制浏览器完成：

第一版目标平台已确定为**微信公众号**（2026-09-03）。先打通一个公众号的图文流程，再扩展其他平台。

- 用户在浏览器中登录目标平台。
- Agent 打开发布页面并填写标题、正文、图片等内容。
- 发布前展示最终预览和目标账号。
- 用户确认后执行真实发布。
- 记录发布状态、时间、目标平台和失败原因。
- 遇到验证码、二次验证或页面异常时暂停，并让用户接管。
- Webhook 失败后可以在幂等保护下重试；公众号结果不明确时不得自动重试，需先人工核对平台状态。

## 主要页面

### 文章工作区

- 文章列表。
- 文章编辑器和预览。
- Agent 对话区。
- 搜索来源和事实核查结果。
- 草稿差异与历史版本。
- 配图确认和生成结果。

### Skills

- 内置 Skill 列表。
- 已安装 Skill 列表。
- 安装、启停、更新和卸载。
- 查看 Skill 的用途和权限。

### 发布

- 选择平台和账号。
- 发布前预览与确认。
- 查看发布过程、结果和历史记录。
- 失败重试或用户接管。

### 设置

- 模型与 API Key。
- Firecrawl 配置。
- 图片模型配置。
- 浏览器与发布配置。
- 本地数据和应用设置。

## 改版优先级

1. 文章工作区与对话式改稿。
2. Firecrawl 求实与来源展示。
3. Skills 安装和运行机制。
4. 图片提示词确认、文生图与图生图。
5. 浏览器自动发布。

原有的任务统计和批量模板调试已从主界面移除。Webhook 账号和复杂定时策略不是本次改版的核心，只作为兼容能力保留。

- 已有文章三栏工作区、Agent 候选稿接受/拒绝、来源展示和图片提示词确认。
- 对话会先通过文字模型识别改稿、配图或准备发布。配图要求直接进入提示词卡，发布要求只打开账号与内容预览；混合或结合近期对话后仍不明确的要求先澄清。识别失败不自动改稿，也不能跳过生图或发布审批；当前不是可自主执行多步骤的通用 Agent。真实模型已通过六次固定表达验收，覆盖否定、配图、发布预览、仅改文字、混合动作和澄清后续选择，并确认识别没有创建改稿、图片、审批或发布任务；报告见 `artifacts/live-conversation.json`，不代表所有自然语言表达均正确。
- 连续对话会读取本篇文章近期最多 20 条文字记录，总长不超过 16,000 字符、单条最多 4,000 字符，超出部分截断。改稿、配图与动作识别共用这份上下文；优先使用当前要求和正文，不跨文章读取，不从历史继承工具权限、事实结论或审批。候选稿的接受/拒绝状态会注明，旧候选正文不重新传入模型。
- 配图提示词、配图失败、澄清与准备发布的对话已保存；刷新或重启后仍可查看。历史提示词只作为文字记录，不会恢复生图或发布授权；未提交的确认卡仍需重新提出要求。刷新后的改稿记录显示接受/拒绝结果，不把上轮改稿 Skill 标成后续配图正在使用的 Skill。
- 对话改稿已接入逐条事实核查：从发送时正文选取最多 6 条关键说法，分别通过 Firecrawl 搜索，展示“来源支持、证据反驳、存在争议、无法确认”、原句、摘录、来源和时间。核查结论进入改稿提示，仍须用户审阅后接受。
- 核查不是全文准确性保证：长文只从前 30,000 字符提取说法；仅有搜索摘要、引文对不上或证据不足时不能显示为来源支持。失败、关闭搜索或 Skill 无搜索权限时明确标记，刷新会恢复本轮报告，不沿用旧结论。核查需要模型与检索额度。
- 改稿已使用发送时的正文快照（含未保存编辑），展示文字增删及格式、链接、媒体标记；生成中的 HTML 不直接执行。旧版本、旧候选稿或缺失基准不能覆盖新正文，接受与审计记录一起提交。
- 候选稿待确认时可以继续在对话中提出改稿要求。新一轮以候选稿为输入，但差异仍与最初发送的正文比较；新稿完整生成后才替代上一版，生成或审计写入失败会保留上一版。只有最新候选稿可以接受，迭代过程不创建文章版本；继续配图或发布前仍须先接受或放弃候选稿。继续修改时的事实核查明确标记为基于候选稿，不能冒充当前正文的核查结果。
- 正文的首个一级标题作为文章标题随版本保存；用户或 Agent 修改后，文章列表、历史恢复和后续发布使用同一标题，不再沿用旧标题。
- 状态刷新、保存返回及应用内导航会保留未保存编辑；刷新或关闭前提示返回保存。未保存内容目前仅在本次应用会话暂存，不能替代手动保存，也不保证崩溃恢复。
- 工作区已支持宽屏三栏、普通窗口双栏与资料抽屉、小窗口正文/对话标签；导航可收起。切换面板保留正文、未发送要求和正文滚动位置，待确认事项可直达；短窗口允许纵向滚动。
- 已内置专业改写、轻松表达、创意写作、新闻求实、标题优化、结构重写和公众号风格 7 个 Skill。用户 Skill 支持单文件或文件夹安装；目录可携带被说明链接的参考资料，但拒绝脚本和越界路径。安装与更新先预览确认，显示权限变化并保留原启停状态。对话可自动按触发词匹配，也可选择或用 `$skill-key` 明确调用；每轮记录实际顺序、原因、版本、权限和资料。停用、卸载或撤回权限会阻止新的模型或工具请求。
- 配图会先生成可编辑提示词；确认后才调用文生图或图生图。确认绑定文章、提示词、画幅和参考图且只能使用一次；图生图会直接预览本轮参考图。生成结果先进入选择卡，不自动插入正文，用户选中并确认后才写入编辑器；重新生成前需再次确认并明确提示会产生额度消耗。
- 配图提示词与改稿一样使用发送时的正文快照，包含未保存修改；缺少基准或过期版本不能提交。声明图片生成或图片编辑能力的 Skill 可按触发词自动匹配，也可在选择器或 `$标识` 中明确调用其他 Skill；提示词会加载 Skill 说明和引用资料，并显示名称、版本、匹配原因、权限与资料。配图 Skill 在请求期间被停用、卸载或撤回权限时，本轮结果作废。Skill 只指导提示词，图片权限不能代替用户确认，也不会在确认前调用图片模型。
